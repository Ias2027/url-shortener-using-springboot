# snip — URL Shortener

A full-stack URL shortener built for placement prep. Spring Boot (Java) backend,
MySQL database, vanilla JS frontend. Every short link's click count is tracked.

## Why this project, and what it demonstrates

- **Algorithmic depth**: short codes are generated by Base62-encoding the
  database auto-increment id (see `UrlShortenerService.java` — read the
  comments there first, that's the part interviewers probe hardest).
- **REST API design**: clean separation between the JSON API (`/api/urls/**`)
  and the actual redirect endpoint (`/r/{code}`).
- **Standard Spring layering**: Controller → Service → Repository → Entity,
  with DTOs so the API contract doesn't leak your DB schema.
- **Validation & error handling**: bean validation on input, a global
  exception handler for clean error responses.

## Running locally

**Prerequisites:** Java 17+, Maven, MySQL running locally.

1. Create the database (or let it auto-create — see `application.properties`,
   `createDatabaseIfNotExist=true` is already set):
   ```sql
   CREATE DATABASE IF NOT EXISTS url_shortener;
   ```
2. Update `src/main/resources/application.properties` with your local MySQL
   username/password if they differ from `root`/`root`.
3. Run it:
   ```bash
   mvn spring-boot:run
   ```
4. Open **http://localhost:8080** — the frontend is served automatically.

## API endpoints (for testing with Postman, or explaining in an interview)

| Method | Endpoint                  | Description                          |
|--------|----------------------------|---------------------------------------|
| POST   | `/api/urls/shorten`        | Body: `{"url": "...", "expiresInMinutes": 60}` (expiry optional) |
| GET    | `/api/urls/{code}/stats`   | Returns click count, created/expiry dates |
| GET    | `/r/{code}`                | Redirects to the original URL (302), increments click count |

## Deploying to a free cloud platform (Render)

1. Push this project to a GitHub repo.
2. On Render.com: **New → Web Service**, connect your repo. Render detects
   the `Dockerfile` automatically.
3. Add a managed MySQL database (Render, PlanetScale, or Railway all have
   free/cheap tiers) and set these environment variables on your web service:
   - `DB_URL` = `jdbc:mysql://<host>:<port>/<dbname>`
   - `DB_USERNAME`
   - `DB_PASSWORD`
   (`application.properties` already reads these via `${DB_URL:...}` syntax —
   this is exactly why they're written that way, so the same code works
   locally and in production without editing files.)
4. Deploy. Render builds the Docker image and gives you a public URL.

## Things you should be able to explain cold in an interview

1. **Walk through what happens end-to-end** when a user submits a long URL:
   frontend `fetch()` → `UrlApiController.shorten()` → `UrlShortenerService.createShortUrl()`
   → save to DB (get id) → `encode(id)` → save again with the short code → JSON response.
2. **Why Base62 encoding of the id, instead of a random string?** No collisions
   possible, since the id is already unique — see the big comment block at the
   top of `UrlShortenerService.java`.
3. **Why 302 redirect, not 301?** So click tracking stays accurate (see comment
   in `UrlRedirectController.java`).
4. **Why DTOs instead of returning the entity directly?** Decouples API shape
   from DB schema.
5. **How would you scale this?** Talking points: add a cache (Redis) in front
   of the DB for hot short codes, add an index on `shortCode` (already done
   here), consider a distributed id generator (like Twitter Snowflake) if you
   outgrow a single auto-increment column.

## What you should do before putting this on your resume

Don't just paste this in — actually run it locally, break something on
purpose (e.g., remove the unique constraint and see what happens with
duplicate codes), and re-read `UrlShortenerService.java` until you can
explain `encode()` on a whiteboard with a real number, by hand.
